# Internal contract review, 20 November 2026

> This project is not audited, endorsed or operated by Zama. Use at your own risk. This was an internal, adversarial self-review (a separate review pass reading the code cold), not a professional audit.

Scope: `DeepSecretGame.sol`, `PearlCoin.sol`, `SecretFishNFT.sol` at commit `a50bbcc`, against the confidentiality matrix (GAME_SPEC §7) and the Sambar rules (SAMBAR_EMBER §1–2). All fixes below are covered by tests (39 passing).

## Fixed

| # | Severity | Finding | Fix |
|---|---|---|---|
| H-1 | High | `authorizeSession` accepted any EOA as a key. Anyone could register another player's wallet as *their* session key; that wallet then acted for the attacker, and after expiry every call reverted, locking the victim out permanently. | The key co-signs `keccak256(abi.encode(game, chainid, player, expiresAt))`; `authorizeSession(key, expiresAt, v, r, s)` checks it with `ecrecover`. Test: "refuses to bind an address that did not co-sign". |
| H-2 | High (confidentiality) | Whether a player has a net is public. Against a bucket with no net, a paid snatch that returns a Sandal Jepit could only mean the target was a Secret: snatching was a Secret detector. | **Ghost net**: every snatch is also guarded with public odds `ghostPer256` (32/256 in the demo season) drawn under encryption (`FHE.randEuint8`). A Sandal now means "net, ghost or Secret", never provably Secret. A ghost catch pays the owner the bait like a net. Test: "hides Secret immunity behind a public-odds ghost net". |
| M-1 | Medium (fairness) | `snatch(victim, fishId)` is visible in the mempool; an online victim (or bot) could front-run it with `setNet` on that fish and always win the bait. | A new net is stored as `netNext` and only arms after `wetSeconds` (20 s demo), longer than a block. Test: "arms a new net only after wetSeconds". |
| L-1 | Low | `restockNpc` set `npcFresh = 6` even with 2 leftovers, so the last NPC snatches underflowed. | `npcFresh += 6`. Test: "keeps counting Pak Kumis's leftovers". |
| L-2 | Low (fairness) | `PearlCoin` inherited public ERC-7984 transfers: sybils could farm free starter coins and funnel them to one account. | Player-to-player transfers revert with `TransfersDisabled`; only the game mints and burns. Test: "blocks player-to-player Pearl transfers". |
| Info | — | `_shareBucket` could scan a very long history; redundant ACL grants in `_giveSack`; `_safeMint` could strand a flex for a contract wallet that rejects ERC-721. | Scan bounded to the newest 120 records; redundant grants removed; `_mint`. |

The optimizer now runs with `runs: 1` to keep `DeepSecretGame` under the 24,576-byte limit (24,274 bytes); FHE work dominates gas, so the runtime cost is negligible.

## Accepted, documented

- **A refused flex is public.** Flexing a non-Secret publicly decrypts it and returns it to the bucket, where everyone knows what it is. The owner already knows the tier, so the UI only offers "Pamerkan" for Secret fish.
- **The rod-upgrade "paid" bit is public** (it must be, to raise the public rod level): it reveals whether the balance covered the price at that moment.
- **ACL grants cannot be revoked.** A leaked session key keeps read access to handles it was granted; revoking stops it from acting. Sessions last at most 7 days.
- **Unpaid snatches still use up cooldowns and mark the fish as targeted.** With many funded sybil accounts someone could drain Pak Kumis's practice bucket; anyone can restock it after 3 minutes.
- **Counters** (`castCount` uint16, fish ids truncated to uint32 inside the net comparison) overflow only far beyond any realistic season.

## Checked and fine

Decryption proofs are bound to the stored handles (`FHE.checkSignatures`), and a new request creates a new handle, so proofs cannot be replayed; double finalisation is blocked by state flags. Only the owner can flex, and snatched or NPC records carry `isSecret = false`, so a Secret cannot be duplicated into an NFT. Thief and victim records are complementary encrypted selects, so a fish is never duplicated or lost. The Secret quota can never be exceeded and stays private until the season ends. Gas, events, reverts and FHE depth never depend on encrypted values: every branch is on public data. There is no practical reentrancy, and `mint`/`burn`/`shareBalance`/`setGame` are restricted. Measured gas stays under the Sepolia per-transaction cap (SPIKE_LOG S23).
